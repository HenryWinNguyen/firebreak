## Goal
Async SQLAlchemy models plus Alembic migrations for alerts, incidents, evidence
and evidence blobs, and the repositories the ingest and tool-gateway tasks use.

## Mandatory reading
- `docs/CONTRACTS.md` §1; `firebreak/models/{alert,incident,evidence}.py`; `docs/ARCHITECTURE.md` §2, §3, §13
- `firebreak/config.py` (`database_url`)

## Patterns to mirror
- Contracts in `firebreak/models/` are the source of truth. DB rows map to them 1:1 and never redefine them

## Definition of done
- [ ] `firebreak/db/engine.py` (async engine/session from `Settings.database_url`), `firebreak/db/tables.py`
- [ ] Alembic is set up under `firebreak/db/migrations/` with `firebreak/db/alembic.ini`. The initial migration creates `alerts` (unique on idempotency key), `incidents`, `incident_alerts`, `evidence`, `evidence_blobs`
- [ ] `AlertRepository.insert_if_new(alert) -> bool` (False when it's a duplicate, race-safe using `ON CONFLICT DO NOTHING`)
- [ ] `IncidentRepository`: `find_open_for_cluster(cluster, now)`, `create(incident)`, `attach_alert(incident_id, alert_id, service)`, `get(id)`
- [ ] `PostgresEvidenceSink` implements `EvidenceSink` (record + exists)
- [ ] Tests run against real Postgres (the CI service / `docker compose up postgres`), using `FIREBREAK_TEST_DATABASE_URL`. Each test runs in a rolled-back transaction or a fresh schema
- [ ] Duplicate insert, concurrent duplicate insert, and the open-incident lookup boundary (window just closed) are tested

## Verify command
```bash
docker compose up -d postgres && make test-db; docker compose down
```

## Out of scope
- Agent runs, tool calls, actions and approvals tables (later milestones)
