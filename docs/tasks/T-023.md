## Goal
A `PostgresIncidentGrouper` that implements `IncidentGrouper`. An alert joins
the open incident of its dependency cluster if that incident's window hasn't
closed, and otherwise opens a new incident.

## Mandatory reading
- `docs/ARCHITECTURE.md` §3; `firebreak/models/incident.py`; `config/service_graph.yaml`; `firebreak/db/` from T-022

## Patterns to mirror
- Repositories from T-022

## Definition of done
- [ ] `service_graph.py` loads and validates the YAML (unknown service → its own singleton cluster, with a warning log)
- [ ] The window is 60s, configurable. `critical` alerts set `window_closes_at = now` (investigate right away) but still group with an already-open incident
- [ ] Incident severity is the max over its alerts. `services` is the union
- [ ] Concurrency-safe: two alerts from one cluster arriving together produce one incident (advisory lock or a unique partial index; tested)
- [ ] An S10-style test: 15 alerts across gateway/orders/inventory within the window → 1 incident with all 15 alerts

## Verify command
```bash
docker compose up -d postgres && make test-ingest; docker compose down
```

## Out of scope
- Starting investigations (M5 moves the window into a Temporal timer)
