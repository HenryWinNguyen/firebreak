## Goal
The narrow, typed read tools from CONTRACTS §3.4, registered in a `ToolRegistry` and
callable through the T-032 gateway, so an agent can investigate a live Shopfloor incident.

## Mandatory reading (before writing any code)
- `CLAUDE.md`
- `docs/CONTRACTS.md` §2.2, §2.4–§2.6, §3.3, **§3.4**
- `docs/ARCHITECTURE.md` §6, §8
- `firebreak/tools/registry.py`, `firebreak/tools/gateway.py`, `firebreak/tools/context.py`, `tests/tools/fakes.py`
- `firebreak/models/evidence.py`, `firebreak/ingest/service_graph.py`

## Patterns to mirror
- `firebreak/tools/registry.py`: `register(..., access=ToolAccess.READ)`, args models with `extra="forbid"`
- `firebreak/llm/client.py`: httpx usage, timeouts, typed errors
- `firebreak/config.py`: pydantic-settings (here with prefix `FIREBREAK_TOOLS_`)

## Definition of done
- [ ] `firebreak/tools/settings.py`: `ToolSettings` (`FIREBREAK_TOOLS_` prefix): `prometheus_url`
      (default `http://localhost:9090`), `loki_url` (`http://localhost:3100`), `shopfloor_urls`
      (service → base URL, defaults from CONTRACTS §2.1 on localhost), `shopfloor_admin_token` (SecretStr,
      default `dev-admin-token`), `http_timeout_s`.
- [ ] Adapters in `firebreak/tools/adapters/` (`prometheus.py`, `loki.py`, `shopfloor.py`) behind small
      Protocols (ARCH §6 `MetricsAdapter` shape), one shared `httpx.AsyncClient` per adapter, typed errors
      (`ToolError` subclasses from `firebreak/tools/errors.py`) for HTTP errors, timeouts, and backend
      `status: error` bodies. No adapter method can issue a non-GET request; the Shopfloor adapter
      exposes ONLY `GET /admin/deploys` (never `/admin/chaos`; a test asserts no other path is reachable).
- [ ] `firebreak/tools/read_tools.py`: `build_read_registry(settings, adapters=None) -> ToolRegistry`
      registering exactly the six §3.4 tools with the arg bounds from the table, `ToolAccess.READ`,
      and the right `EvidenceKind` on every `ToolOutput`. `query` strings are passed through verbatim
      (reproducible); results are rendered compactly (e.g. series as `labels → [t, v]` rows, downsampled
      to fit `max_output_chars`, with a note when truncated) while the full JSON goes to the raw payload.
- [ ] `promql_range`/`logql_query` compute the window from `minutes_back` against an injectable clock
      (aware UTC), and the exact resolved query + window is recorded in `Evidence.query`.
- [ ] Tests with `respx` (or `httpx.MockTransport`) for every tool: happy path, empty result, backend
      error, timeout, oversized result truncation, arg-bound rejection via the gateway (`invalid_args`),
      and that log lines come back wrapped as untrusted by the gateway.
- [ ] No network in tests. No silent failures: every caught exception is re-raised, logged with context, or turned into a typed error
- [ ] PR description has a `## Progress entry` (builders don't edit PROGRESS.md)
