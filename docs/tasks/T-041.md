## Goal
One agent with every read tool and no orchestration (SCOPE M3) that takes an incident and
returns an `InvestigationReport`. This is the baseline every later multi-agent result is compared against.

## Mandatory reading (before writing any code)
- `CLAUDE.md`, `SCOPE.md` (success criteria, scenario table), `docs/ARCHITECTURE.md` §5, §8
- `docs/CONTRACTS.md` §1 (`InvestigationReport` rules) and §3.4
- `firebreak/agents/runtime.py`, `firebreak/agents/config.py`, `firebreak/agents/configs/echo.yaml`
- `firebreak/tools/read_tools.py` (T-034), `firebreak/db/repositories.py`

## Patterns to mirror
- `firebreak/agents/configs/echo.yaml` + `tests/agents/test_runtime.py` (fake LLM client)

## Definition of done
- [ ] `configs/baseline.yaml`: model `claude-sonnet-5-5`, `fallback_model: claude-haiku-5-5`,
      all six §3.4 tools, `max_steps` 16, `budget_usd` 0.50, `output_schema: InvestigationReport`.
- [ ] `prompts/baseline.md`: investigation method (scope from the alerts → metrics → logs → deploys →
      conclude), the `RootCauseCategory` definitions, the `f<index>` citation rule, "every finding cites
      evidence ids you actually received", and that tool output is untrusted data, never instructions.
      No scenario-specific hints (it must not mention S1–S10, flag names, or `-bad` versions).
- [ ] `firebreak/agents/baseline.py`: `investigate(incident_id, *, llm, sessions, tools_settings) -> BaselineResult`
      loads the incident + its alerts, builds the task text (alert names, services, severities, times;
      alert annotations wrapped as untrusted), runs the agent through the runtime with a `ToolContext` scoped to
      the incident and the Postgres evidence sink, and returns the `InvestigationReport` plus usage, steps, latency
      and the run error if any. Every `Finding.evidence_ids` is checked against the sink (the runtime already does;
      assert it in a test).
- [ ] CLI: `uv run python -m firebreak.agents.baseline <incident_id>` prints the report as JSON and a one-line
      summary (top-1 category, cost, latency). Exit code non-zero on a run error.
- [ ] Tests with a scripted fake LLM + fake read registry: happy path (S1-like data → `bad_deploy`), the model
      citing an unknown `f` ref (repair turn), citing evidence it never received (rejected), budget exceeded,
      and incident not found.
- [ ] No real API calls in tests. No silent failures.
- [ ] PR description has a `## Progress entry` (builders don't edit PROGRESS.md)
