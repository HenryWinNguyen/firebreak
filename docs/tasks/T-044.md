## Goal
Make a baseline run reproducible offline (ARCH §9 "Replay" mode): record every LLM response and every
read-tool output once on the live stack, then replay the identical run in CI for $0, with stale
recordings detected when a prompt or tool changes.

## Design (lead decision)
- Determinism: wrap a run in `firebreak.models.common.deterministic(seed=<scenario id>, at=<recorded start>)`.
  It seeds `new_id` and freezes `utcnow`. All clocks in the run path must go through `utcnow()`
  (`read_tools.py` and the LLM client currently call `datetime.now` directly: fix both).
- LLM: keep the existing hash-keyed `FixtureStore` (key = model, system, messages, tools). With
  deterministic ids/clock the messages are identical on replay, so a hash miss means the prompt, tools or
  model changed → **stale**: raise `StaleRecordingError` naming the scenario and the first differing step.
  Never fall through to a live call in replay mode.
- Tools: a `Cassette` wraps the read-tool adapters (not the gateway, so the gateway, defang and evidence
  path still run for real). Record mode: real adapter, store `(adapter method, normalized args) → raw
  result` in order. Replay mode: return the recorded result for the same key; a key not in the
  cassette → `StaleRecordingError`.
- Layout: `evals/recordings/<agent>/<scenario>/{llm/<key>.json, tools.jsonl, meta.json}` with `meta.json`
  holding the seed, `at`, model ids, prompt sha256, and the recording date. No secrets (assert the admin
  token and API key never appear in any file).
