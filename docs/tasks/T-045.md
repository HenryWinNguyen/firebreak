## Goal
SCOPE M4 "done when": `make eval` scores the baseline over the recorded scenarios and saves the
results to the DB, and `evals/REPORT.md` is generated from them.

## Definition of done
- [ ] Migration `0002`: `eval_runs` (id, started_at, mode, agent, git_sha, prompt_sha256) and
      `eval_results` (run id, scenario id, top1, top3, cited_kinds_ok, report_valid, cost_usd, latency_s,
      steps, error, report JSONB). Repository methods; compare_metadata drift test still passes.
- [ ] `python -m firebreak.evals run --mode replay --agent baseline [--scenarios s01,s02]`: for each scenario
      with a recording, create the incident from the recorded alerts, run the baseline under the T-044
      cassette in replay mode, grade (T-043), store. Missing recording → reported as "not recorded", not a
      failure. Stale → the run fails with the scenario named.
- [ ] Replay is fully offline: the runner injects the T-044 replay cassette adapters into `investigate` (its
      `registry=` hook) inside `deterministic(...)`; it never calls `build_default_adapters` in replay mode.
      Test with a transport that raises on any request.
- [ ] `--mode record` exists but refuses to run unless `FIREBREAK_EVAL_LIVE=1` and an API key are set
      (it spends money; T-042 uses it).
- [ ] `python -m firebreak.evals report` writes `evals/REPORT.md`: per-scenario table + summary
      (top-1/top-3, p50/p95 latency and cost) for the latest run per agent.
- [ ] Tests with a synthetic recording (built via the T-044 test helpers): end-to-end replay → rows in both
      tables → REPORT.md content. No network, no API key.
- [ ] No silent failures
- [ ] PR description has a `## Progress entry` (builders don't edit PROGRESS.md)
