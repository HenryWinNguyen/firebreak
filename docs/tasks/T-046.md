## Goal
Tighten the T-044 record/replay edges found in its Opus review, and make evidence ids independent of
backend timing at the source (the gateway) instead of relying on cassette ordering alone.

## Mandatory reading (before writing any code)
- `CLAUDE.md`, `docs/tasks/T-044.md` (design), `docs/ARCHITECTURE.md` §8–§9
- `firebreak/llm/fixtures.py`, `firebreak/evals/cassette.py`, `firebreak/tools/gateway.py`, `firebreak/tools/untrusted.py`

## Definition of done
- [ ] Nonce normalization in `fixture_key` matches ONLY real wrapper tags (`<untrusted-data … nonce="X">` and
      `</untrusted-data nonce="X">`), never nonce-shaped text in content. Nonces stay cryptographically random
      in all modes (lead decision: never seed them). Tests: two requests differing only in a nonce-shaped literal
      inside content hash differently; real tags still normalize.
- [ ] Secret scan: warn (log) when a configured secret is shorter than 8 chars and so can't be scanned safely;
      also scan for base64 and URL-encoded forms of each secret. Tests.
- [ ] Overwrite is crash-safe: move the old recording aside, move the new one in, then delete the old one; the
      staging dir name is unique per run (e.g. includes the pid + a random suffix). Test that a failure mid-swap
      leaves the old recording intact.
- [ ] `replay_run` fails with `StaleRecordingError` if recorded tool calls were not consumed. Test.
- [ ] Gateway: `ev_id = new_id("ev")` is assigned at the start of `invoke` (right after the call id) and passed
      through to `_record`, so evidence ids follow call-start order regardless of completion order. Test with
      handlers that finish in reverse order under `deterministic()`. The existing T-044 round-trip tests still pass.
- [ ] No silent failures
- [ ] PR description has a `## Progress entry` (builders don't edit PROGRESS.md)
