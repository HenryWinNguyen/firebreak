## Goal
Henry chose a **hybrid model plan** (2026-10-28): iterate on a free local model (Ollama, OpenAI-compatible
API), and spend on Claude only for the recorded headline runs. Add a second `LLMClient` implementation, route
each request to a provider by model name, and add a `baseline-local` agent config so `make eval`-style runs
work against a local model for $0.

## Mandatory reading (before writing any code)
- `CLAUDE.md`, `docs/CONTRACTS.md` (LLM section), `firebreak/models/llm.py` (`LLMRequest`/`LLMResponse` are
  **Anthropic-shaped**; that contract does NOT change, so translate inside the new client)
- `firebreak/llm/{client,settings,pricing,pricing.yaml,errors,ratelimit,fixtures}.py`
- `firebreak/agents/runtime.py` (how tool_use/tool_result blocks and stop reasons are consumed)
- `firebreak/agents/baseline.py`, `firebreak/agents/configs/baseline.yaml`
- `firebreak/evals/{__main__,runner}.py` (`require_live_env`, how `--agent` selects a config)

## Patterns to mirror
- `AnthropicLLMClient`: retries, Retry-After, rate limiting, typed errors, cost via pricing.
- Tests with `httpx.MockTransport` (see `tests/tools/` adapters); no real server in unit tests.

## Definition of done
- [ ] `firebreak/llm/openai_compat.py`: `OpenAICompatLLMClient` implements `LLMClient` against
      `POST {base_url}/chat/completions` (httpx). Translates Anthropic-shaped `system`/`messages`
      (text, `tool_use`, `tool_result` blocks) + `ToolSpec`s into OpenAI chat messages/`tools`, and the reply's
      `content`/`tool_calls`/`finish_reason`/`usage` back into an `LLMResponse` (`tool_use` blocks with the
      provider's call ids; `finish_reason` `tool_calls`→`tool_use`, `stop`→`end_turn`, `length`→`max_tokens`).
- [ ] Malformed tool-call arguments from a small model (invalid JSON, non-object) never crash the run and are
      never silently dropped: they become a `tool_use` block the gateway rejects as invalid args (visible to the
      model as an error result), or a typed error the runtime already handles. Pick one, document it, test it.
- [ ] Provider routing by model: `pricing.yaml` entries get `provider: anthropic | openai_compat` (default
      `anthropic` for existing entries). A routing client (or `build_llm_client`) sends each request (including
      the fallback model) to the matching client. An unknown model is a typed error, never a silent $0.
      Add `qwen3:8b` with `provider: openai_compat` and all prices `0.0`, with a comment that it is local.
- [ ] Settings (`FIREBREAK_LLM_`): `openai_base_url` (default `http://localhost:11434/v1`),
      `openai_api_key: SecretStr | None` (Ollama needs none; never logged), `openai_timeout_seconds`
      (default generous, e.g. 300, since local models are slow). Connection refused → clear typed error that
      says to start Ollama (`ollama serve`) and pull the model.
- [ ] Record/replay works for either provider unchanged (fixture keys already include the model). Replay
      never builds any live client of either kind.
- [ ] `firebreak/agents/configs/baseline-local.yaml`: identical to `baseline.yaml` except `name: baseline-local`,
      `model: qwen3:8b`, no fallback (or another local model), `budget_usd` kept (cost is $0, the cap stays as a
      guard). Same prompt and tools, so local vs Claude results are comparable.
- [ ] Eval runner: `--agent baseline-local` works; recordings land under `evals/recordings/baseline-local/` and
      never mix with Claude ones. `require_live_env` requires `FIREBREAK_EVAL_LIVE=1` always, and
      `ANTHROPIC_API_KEY` **only** if the agent config (model or fallback) routes to `anthropic`.
- [ ] Tests (no network): translation both ways incl. multi-tool turns and tool_result round trip; finish
      reason mapping; malformed args; routing incl. fallback across providers; unknown model; usage → cost 0;
      connection-refused message; record guard with and without the Anthropic key. One optional test marked
      `integration` that hits a real Ollama at `openai_base_url`, skipped unless `FIREBREAK_OLLAMA=1`.
- [ ] No silent failures
- [ ] PR description has a `## Progress entry` (builders don't edit PROGRESS.md)
