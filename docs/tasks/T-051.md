## Goal
Record mode needs a live incident per scenario (`--incident S1=<id>`). Today that means hand-applying each fault,
waiting for the alert to become an incident, looking up its id, recording, and resetting — 7 error-prone cycles.
Add a driver that does it per scenario from the scenario file, and make one scenario's failure not abort the batch.

## Definition of done
- [ ] `firebreak/evals/live.py`: `drive_scenario(scenario, ...)`:
      1. refuse unless the stack is clean (no firing alerts for the scenario's expected alertnames);
      2. apply setup in the documented order via the Shopfloor admin API (admin token from settings, never logged);
      3. run the scenario's `load` (async load generator, bounded concurrency, stopped in `finally`);
      4. poll the **live** DB read-only for a new incident (created after step 2) whose alerts match any
         `expect.alerts` (alertname + service); timeout configurable (default 600 s) → typed error;
      5. call the existing `record_scenario` with that incident id;
      6. always (in `finally`): stop load, reset chaos + deploy, and wait until the expected alerts stop firing
         (timeout → logged error, and the next scenario refuses to start on a dirty stack).
- [ ] CLI: `run --mode record --agent NAME --drive [--scenarios s01,...]` uses the driver instead of `--incident`
      (mutually exclusive). Still requires `FIREBREAK_EVAL_LIVE=1` (+ Anthropic key only if the agent routes there).
- [ ] Per-scenario errors: in record mode (driven or not), an error in one scenario (LLM error incl.
      `ContextOverflowError`, timeout, no incident) is logged, reported in the summary as `S<n>: error: ...`, and the
      batch continues. The exit code is non-zero if any scenario errored. Secret-scan failures still abort the batch.
      Replay-mode behaviour (stale aggregation) is unchanged.
- [ ] The admin API is used only by this eval driver; nothing is registered as an agent tool.
- [ ] Tests (no network, no Docker): `httpx.MockTransport` for Shopfloor/Alertmanager, a fake incident source;
      setup order; teardown runs on every failure path (incl. KeyboardInterrupt/CancelledError); dirty-stack refusal;
      incident timeout; batch continues after one scenario errors; exit code; `--drive` and `--incident` exclusive.
- [ ] No silent failures
- [ ] PR description has a `## Progress entry`
