## Goal
S5 leaks ~128 KB per orders request, and the leak is freed only by a process restart. The T-051 driver keeps load
running until teardown and never restarts orders, so a slow local-model investigation could grow orders past
several GB on a 16 GB laptop that is also running Ollama, and the stack never comes clean afterwards. Make S5
bounded and resettable so it can be driven like the other scenarios.

## Definition of done
- [ ] Shopfloor orders: `POST /admin/chaos/reset` also releases the S5 leak buffer (clear the list, `gc.collect()`),
      so RSS can fall back below the HighMemory threshold without a restart. Admin-only, as today. Shopfloor test:
      leak some buffers, reset, the list is empty. (RSS release is best-effort; document it.)
- [ ] Scenario model: `load.hold` = `until_teardown` (default, today's behaviour) | `duration` (stop load after
      `duration_s`; the fault's effect persists without new requests). Validated; existing YAMLs unchanged.
- [ ] `s05.yaml`: `hold: duration`, so the leak stops growing once the alert has had time to fire.
- [ ] Driver RSS guard: while driving, poll orders RSS from Prometheus (the metric HighMemory uses) every poll
      interval; above `FIREBREAK_EVAL_DRIVE_MAX_ORDERS_RSS_MB` (default 2500) → stop load, fail the scenario with a
      typed error, and tear down. Prometheus unavailable for the guard → fail the scenario (never run unguarded).
- [ ] Tests (no network, no Docker): reset clears the buffer; `hold: duration` stops load after `duration_s`; the RSS
      guard trips and tears down; guard fails closed when Prometheus errors; `until_teardown` unchanged.
- [ ] No silent failures
