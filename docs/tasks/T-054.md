## Goal
The T-049 run aborted S6 with `OrdersRssGuardError: Prometheus has no process_resident_memory_bytes
sample for orders`. S6 stalls orders on Redis timeouts, so two Prometheus scrapes of orders timed out
(10:47–10:48 on 2026-10-29, `scrape_duration_seconds` = 10s, `up` = 0). A failed scrape marks the series
stale, so the instant query returns nothing. RSS was ~755 MiB the whole time. The guard should ride out
a short blind window and still fail closed if it stays blind.

## Definition of done
- [ ] New setting `FIREBREAK_EVAL_DRIVE_RSS_BLIND_GRACE_S` (default 180, `gt=0`) in `DriveSettings` and `DriveConfig`, wired where the config is built
- [ ] `rss_guard`: when `orders_rss_mb` can't read a value (HTTP error or no sample), log a WARNING with the reason and how long it has been blind, and keep polling. Raise `OrdersRssGuardError` only once it has been blind for longer than the grace period (the message says so and names the setting). A good read resets the blind clock. Over-limit still trips on the first read
- [ ] Add a synchronous `orders_rss_mb` check in `drive` right before `gen.start()` (today the guard task and the load start together, live.py ~678). If it can't read the metric, fail closed right away (the driver never starts load unguarded); the grace applies only after load has started. Document this in the docstring
- [ ] Update the module docstring step 3 to describe the grace period
- [ ] Tests (no network, no Docker, use a small grace and poll interval): a gap shorter than the grace doesn't fail the scenario; a gap longer than the grace fails it and tears down; a good read resets the clock; blind at start still fails closed; over-limit still trips. `test_rss_guard_fails_closed_when_prometheus_is_unusable` keeps the fake blind the whole drive, so it now exercises the start check (no 180 s wait); adjust it only as far as needed
- [ ] No silent failures: every blind poll is logged
