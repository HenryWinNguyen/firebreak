## Goal
In the T-049 run, the local model called `logql_query` with `query="level=error"` in both S4 and S6.
That's not LogQL (there's no stream selector), so Loki returned 400 and the agent ran without logs. The
tool description says only "Run a LogQL query against Loki…", so the model has no way of knowing the
labels. Make the description say how to write a valid query.

## Mandatory reading (before writing any code)
- `CLAUDE.md`, `docs/CONTRACTS.md` §2.5 (log fields) and the `logql_query` row in §3.4
- `ops/promtail/` config: the labels are `service` (compose service name), `level` (from the JSON log), `container`
- `firebreak/tools/read_tools.py` (`LogqlQueryArgs`, the `add("logql_query", …)` registration)

## Definition of done
- [ ] The `logql_query` description (and the `query` field description) say a query must start with a stream selector, list the labels `service` (gateway, orders, inventory) and `level`, and give 1–2 short examples, e.g. `{service="orders", level="error"}` and `{service="gateway"} |= "timeout"`. Keep it short: it's sent on every LLM step
- [ ] No change to the args schema, the evidence kind, or the adapter
- [ ] Test: the registered description contains a stream-selector example (guards against regressions)
- [ ] PR description has a `## Progress entry`, and notes that it changes the LLM request hash, so the T-049 recordings must be re-recorded (the lead does that)
