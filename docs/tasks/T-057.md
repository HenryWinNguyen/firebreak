## Goal
`record_run` runs inside `deterministic(seed=<scenario>, at=...)`, so every recording of `s01` produces the same
`ev_…` ids. The eval DB (recording installs a copy of the incident there, runner.py ~411-431) keeps evidence from earlier recordings, so the second recording of a scenario hits
`EvidenceConflictError` ("already recorded for incident <old incident>") on every tool call, the gateway discards
the results, and the agent ends with no citable evidence. The 2026-10-29 T-049 re-record lost S1–S4 and S6 this way
(18 conflicts). Make each recording's seed unique while replay stays exact.

## Definition of done
- [ ] `record_run` uses a seed unique to that recording: the scenario id plus the recording start `at` in ISO form
      (e.g. `s01@2026-10-29T18:04:05.123456+00:00`). The same seed goes into `deterministic(...)` and `meta.seed`
- [ ] `replay_run` is unchanged in behaviour (it already uses `meta.seed`). Existing recordings whose `meta.seed` is
      just the scenario id still replay byte for byte
- [ ] Docstrings (module and `record_run`) describe the new seed
- [ ] Tests: two recordings of the same scenario with different `at` produce disjoint evidence ids; a recording
      replays with identical ids; a seed containing `@` and `+00:00` round-trips through meta.json; an old-format meta (`seed == scenario`) still replays. Update the existing meta
      assertion (~line 293, `meta["seed"] == SCENARIO`) only as far as needed
- [ ] Replay also persists evidence in the eval DB with ids seeded by `meta.seed`. Old-format recordings share
      `seed == scenario` across agents, so replaying baseline and candidate recordings of one scenario into the same
      eval DB would collide too. Confirm this and say so in the PR (the lead re-records every old-format recording;
      don't fix outside owned paths)
- [ ] Docstring of `record_run`: uniqueness relies on callers passing a distinct `at` per recording (runner.py passes
      `utcnow()`); don't add a random component (the seed must be reproducible from meta)
- [ ] No silent failures
- [ ] PR description has a `## Progress entry`
