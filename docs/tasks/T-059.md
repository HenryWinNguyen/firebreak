## Goal
Merge gate G1 says CI runs "replay evals once M4 exists", but nothing does: `make check` doesn't replay, and
`make eval` hardcodes `--agent baseline`, which has no recordings (only `evals/recordings/baseline-local/`). A prompt or
tool-description change can silently make every recording stale. Replay them in CI at $0.

## Mandatory reading (before writing any code)
- `CLAUDE.md`, `docs/AGENT_WORKFLOW.md` §5 (G1)
- `Makefile` (`eval`, `check`), `.github/workflows/ci.yml` (the `check` job's Postgres service)
- `firebreak/evals/__main__.py`, `firebreak/evals/runner.py` (`require_eval_database_name`, `ensure_eval_database`,
  what database URL replay uses and what name it insists on)

## Definition of done
- [ ] `make eval` takes `AGENT ?= baseline-local` and replays every agent dir that exists when `AGENT=all`
      (or document why not). `make eval` with no args replays the committed recordings
- [ ] CI job `replay` (needs Postgres like `check`): runs the replay for every committed agent and **fails** on a
      stale recording or a non-zero exit caused by anything other than graded misses. Graded misses and invalid final
      answers are results, not failures. If the CLI can't tell these apart today, say so in the PR and the lead
      decides (don't edit outside owned paths)
- [ ] The job uses an eval database name that passes `require_eval_database_name`. No API keys, no network LLM
- [ ] Verified on the PR: the `replay` job is green on this branch, and red on a throwaway commit that changes one
      hash in a recording's `meta.json` `llm_steps` (revert it before review; describe it in the PR)
- [ ] PR description has a `## Progress entry`

## Verify command
```bash
make eval && make check
```
