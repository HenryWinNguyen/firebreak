## Goal
T-056's review left two minors. `OrderStore` counts a query after the `await`, so a round trip that raises (timeout,
pool error, Postgres error) is never counted, which undercounts exactly when the DB is in trouble. And the lifespan
wiring (`app.state.store = OrderStore(..., queries=...)`, app.py ~254) has no test; it was only checked live.

## Mandatory reading (before writing any code)
- `CLAUDE.md`, `docs/tasks/T-056.md`, `docs/CONTRACTS.md` §2.4 (`db_queries_total`)
- `shopfloor/orders/app.py` (`OrderStore`, `_count_query`, the lifespan that builds the store)
- `shopfloor/tests/` (the T-056 counter tests and how other tests build the app / fake the pool)

## Definition of done
- [ ] Every DB round trip in the request path is counted when it is attempted (count before the `await`), so a
      round trip that raises is counted too. Normal order still 2, N+1 still quantity+1
- [ ] Test: a round trip that raises still increments the counter (fake connection that raises), and the error still
      propagates (no swallowing)
- [ ] Test: the app built through its lifespan wires the store to the `db_queries_total{service="orders"}` child
      (e.g. a request through the app with a fake pool moves the value in `/metrics`, or assert the store's counter is
      that child). The conftest stack injects `store=FakeOrderStore`, so it never runs the lifespan's
      `store is None` branch: build the app with `store=None` and monkeypatch `orders.app.create_raw_pool` to return the
      existing `FakeRaw`. No real Postgres
- [ ] No change to metric names, labels, alert rules
- [ ] PR description has a `## Progress entry`
