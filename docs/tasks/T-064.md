## Goal
SCOPE M5: Temporal orchestration, acceptance "kill the worker mid-run → the investigation resumes and finishes".
Build `IncidentWorkflow` and the worker process per ARCHITECTURE §4.1–4.4, ending at `REPORT_ONLY` for now (critic is
M6, remediation M8). The agent side (`run_agent` activity, configs, prompts) is T-065, built in parallel against the
same contract; here you stub it in tests. **Same-task comparison (AGENT_WORKFLOW §8):** two builders implement this
spec independently; the lead keeps one. Don't coordinate.

## Definition of done
- [ ] `firebreak/workflows/incident.py`: `IncidentWorkflow.run(incident_id) -> WorkflowOutcome`:
      `load_context` → TRIAGE (`run_agent` "triage"; noise/duplicate → `DISMISSED`) → PLANNING ("supervisor") →
      INVESTIGATING (one `run_agent` per `Plan.tasks`, in parallel, `start_to_close_timeout = task.timeout_s`) →
      SYNTHESIZING ("synthesizer", context carries reports + `degraded_sources`) → `REPORT_ONLY`
- [ ] Timeouts/retries (same for both comparison builds): `load_context`/`set_incident_state` 30 s; triage and
      supervisor 300 s; synthesizer 600 s; specialists `task.timeout_s`. Every activity: max 3 attempts; errors raised as
      `ApplicationError(non_retryable=True)` are not retried
- [ ] Every state change goes through `set_incident_state` before the step runs (so the DB shows where it is),
      including the terminal state (`REPORT_ONLY`/`DISMISSED`/`ESCALATED`) before returning
- [ ] Partial failure (§4.3): a specialist that raises/times out, or returns no valid `SpecialistReport`, goes into
      `degraded_sources`; the rest continue. All specialists failed → `ESCALATED` with `error`. Triage, supervisor or
      synthesizer without valid output → `ESCALATED` with `error` (no silent defaults, no invented plan)
- [ ] The workflow validates each `AgentRunResult.output` into the agent's schema (contract v1.6) and collects all
      `agent_runs` and summed `usage` into the outcome. A `SpecialistReport` whose `agent` differs from the task's agent counts as invalid (degraded)
- [ ] `firebreak/activities/incident.py`: `load_context` (incident + alerts → `IncidentContext`, summary via
      `build_task`) and `set_incident_state` (new `IncidentRepository.set_state`, updates `updated_at`; unknown incident
      raises `IncidentNotFoundError`). Both activities turn `IncidentNotFoundError` into a non-retryable
      `ApplicationError`. DB test for `set_state` (marker `db`). The final report is not persisted in M5 (only in
      `WorkflowOutcome`); a `save_report` activity comes later
- [ ] `firebreak/workflows/worker.py` (`python -m firebreak.workflows.worker`): connects to
      `FIREBREAK_TEMPORAL_ADDRESS` with `pydantic_data_converter`, runs a workflow worker on `ORCHESTRATOR_TASK_QUEUE` and
      an activity worker on `AGENT_TASK_QUEUE` in one process. It registers your activities plus T-065's agent
      activity: `firebreak.activities.agents.build_agent_activities()` returns an object with an async `run_agent`
      method (the activity) and `aclose()`; call `aclose()` on shutdown. If that module isn't importable yet, log that
      agent activities are not registered and run without them. Settings in
      `firebreak/workflows/settings.py`. Graceful shutdown on SIGTERM
- [ ] `start_incident_workflow(client, incident_id)` helper: workflow id `incident-<incident_id>`, id-reuse policy that
      refuses a duplicate start (document which)
- [ ] Tests with `WorkflowEnvironment` and stub activities: happy path; noise → DISMISSED; one specialist fails →
      degraded + REPORT_ONLY; all fail → ESCALATED; invalid supervisor output → ESCALATED; states recorded in order
- [ ] **Kill-the-worker test** (the M5 acceptance, in-process): start the workflow, stop the worker while a specialist
      activity is in flight, start a new worker, and the workflow completes with a report. Activities must be safe to
      re-run (document why `run_agent` re-execution is acceptable: evidence ids are per tool call). Use the
      time-skipping environment so activity timeouts don't cost wall time
- [ ] `tests/activities/__init__.py` stays empty (T-065 adds the same empty file)
- [ ] No `datetime.now`/`uuid4`/random in workflow code; no network or DB in workflow code; mypy --strict clean
- [ ] PR description: `## Progress entry`, and a short "design notes" section (choices you made and why) for the
      comparison
