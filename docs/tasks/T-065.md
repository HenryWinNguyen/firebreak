## Goal
The agent side of M5 (ARCHITECTURE §4.4, §5.2): configs and prompts for triage, supervisor, three specialists and the
synthesizer, all on the local model (`qwen3:8b`, $0), plus the `run_agent` Temporal activity that runs one of them on
its slice of the blackboard. T-064 builds the workflow in parallel against the same contract (`firebreak/models/
orchestration.py`, CONTRACTS v1.6).

## Definition of done
- [ ] Configs in `firebreak/agents/configs/multi-local/`, prompts in `firebreak/agents/prompts/multi/`:
  - `triage` → `TriageResult`, no tools (the summary is in its task)
  - `supervisor` → `Plan`, tool `service_graph`; its prompt lists the specialists that exist (`metrics`, `logs`,
    `deploys`) and what each can see; tasks name only those
  - `metrics` (`promql_query`, `promql_range`, `list_metrics`), `logs` (`logql_query`), `deploys` (`recent_deploys`,
    `service_graph`) → `SpecialistReport`; each must call its tools before answering and cite only returned evidence ids
  - `synthesizer` → `InvestigationReport`, no tools; builds findings only from the specialists' findings (same
    `evidence_ids`), is told which sources were degraded, lowers confidence accordingly
  - Prompts are short (sent every step on a local 32k context) and say the output is JSON matching the schema
- [ ] `firebreak/activities/agents.py`: `build_agent_activities() -> AgentActivities` (reads settings from env, builds
      the DB engine/session factory, LLM client and `ToolSettings` once per process) and `AgentActivities` with
      `@activity.defn(name=ACTIVITY_RUN_AGENT) async def run_agent(self, task: AgentTask) -> AgentRunResult` and
      `async def aclose()`. T-064's worker calls exactly these. Picks the context slice per agent (§4.4: triage gets the summary; supervisor summary + triage;
      specialist summary + its question + affected services; synthesizer summary + reports + degraded sources; never
      other agents' transcripts), loads `<profile>/<agent>.yaml` (profile from `firebreak/agents/settings.py`,
      default `multi-local`), runs the shared runtime with the read-tool gateway and `PostgresEvidenceSink`, closes
      adapters, returns the `AgentRunResult`. A run without valid output is returned, not raised; unknown agent and
      infrastructure errors raise. Unknown agent / bad config raise `ApplicationError(non_retryable=True)`.
      Read adapters (HTTP clients) are built and closed per call, like the baseline
- [ ] Untrusted text stays wrapped (§8): specialist findings passed to the synthesizer are agent output about
      untrusted data; keep the wrapping the runtime already applies and don't unwrap alert text
- [ ] Tests (no network, no LLM): every config loads and resolves its schema and tools; slice builder per agent
      (synthesizer sees reports, specialist doesn't see other reports); `run_agent` with a fake LLM client returns a
      validated output and returns (not raises) an invalid-output run
- [ ] Supervisor prompt: set `timeout_s` only if a task needs more than the default (300 s)
- [ ] `tests/activities/__init__.py` stays empty (T-064 adds the same empty file)
- [ ] PR description has a `## Progress entry`
