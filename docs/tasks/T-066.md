## Goal
Today a workflow only starts by hand. Make ingest start it: every firing, non-duplicate alert the grouper places goes to
`incident-<incident_id>` with signal-with-start (`SIGNAL_ALERT_ADDED`, payload `AlertAdded`), and the workflow waits in
`GROUPING` until the window closes (or a critical alert closes it) before triaging. Read the v1.7 grouping rule in
CONTRACTS §1 first: the Postgres grouper stays the source of truth for membership; the workflow only waits.

## Definition of done
- [ ] `load_context` fills `IncidentContext.window_closes_at` from the incident
- [ ] Workflow: `@workflow.signal(name=SIGNAL_ALERT_ADDED)` handler. After `load_context`, while in `GROUPING`, wait
      until `window_closes_at` (timer from `workflow.now()`; already past → no wait) or until a `critical` `AlertAdded`
      arrives, then continue to triage as today. Signals after the window are logged and ignored. `GROUPING` is
      recorded via `set_incident_state` like every other state. Deterministic (no wall clock)
- [ ] `client.py`: `signal_alert_added(client, incident_id, AlertAdded)` using signal-with-start on
      `ORCHESTRATOR_TASK_QUEUE`, id `incident-<id>`. A workflow that already finished for that id (id reuse rejected) is
      logged at info and not an error
- [ ] API: after `ingest`, for each result with an `incident_id` that is not `duplicate` and not a resolved alert,
      call `signal_alert_added` with that alert's id and severity. The Temporal client is created lazily and cached
      (the API must start and accept webhooks with Temporal down). If signalling fails (Temporal unreachable), the
      webhook still succeeds (alerts are stored), and the failure is logged at ERROR with the incident id and alert id
      (never swallowed silently). Close the client in the lifespan if one was created
- [ ] Tests: workflow waits for the window (time-skipping env: no triage before the window, triage after); critical
      signal closes it early; post-window signal ignored; window already past starts at once. API: created incident →
      signal-with-start called with the right id/payload; duplicate and resolved → not called; Temporal error → 2xx +
      ERROR log (fake client). One end-to-end test: webhook → real `WorkflowEnvironment` → workflow running in GROUPING
- [ ] Existing T-064 tests still pass (update them for the GROUPING wait where needed)
- [ ] PR description has a `## Progress entry`; note the follow-up "reconcile incidents with no workflow" (not built)
