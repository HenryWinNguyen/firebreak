## Goal
Measure the multi-agent system the same way as the baseline (ADR-005): `python -m firebreak.evals run --agent
multi-local --mode record|replay` runs the real `IncidentWorkflow` (in-process Temporal test environment) with the real
agent activities, records every LLM step and tool result, and replays offline at $0 with identical results, graded on
`WorkflowOutcome.report`. Then `make eval AGENT=all` and the CI `replay` job cover it automatically once recordings exist.

The hard part is determinism under parallelism. The baseline is one sequential agent; here specialists run concurrently,
so (a) tool results can't share one call-start-ordered stream, and (b) evidence ids from one global `deterministic(...)`
stream would be handed out in a different order on replay, changing the LLM request hashes.

## Definition of done
- [ ] Design note in the PR (and module docstring): how record and replay stay identical with parallel specialists.
      Expected shape (change it only with a reason): each `run_agent` call runs in its own deterministic context seeded
      from the recording seed plus a stable per-call key (agent + step/question), and has its own tool stream
      (call-start order within that agent run); LLM fixtures stay keyed by request hash. Recordings live under
      `evals/recordings/multi-local/<scenario>/`; the layout is documented
- [ ] `multi-local` is a known eval agent (it is a profile directory, not one yaml: make `agent_config_path`/
      `agent_models`/`agent_providers` handle it without breaking `baseline`/`baseline-local`)
- [ ] Record mode (lead runs it live; needs Ollama): runs the workflow in-process against the live stack with real
      adapters wrapped for recording, writes the recording, stores the result like the baseline. Replay mode: no
      network, no LLM, real gateway/evidence path, raises `StaleRecordingError` on any drift (never falls back to live)
- [ ] Grading: `WorkflowOutcome.report` graded like the baseline's report; `ESCALATED`/`DISMISSED` are graded results
      with the outcome's `error`, not crashes. Latency is the recorded live latency; usage summed across agents
- [ ] The Temporal test environment works in CI's `replay` job (time-skipping or local dev server; if a binary download
      is needed, say so and make it explicit in the Makefile/CI step if required; `Makefile` is owned, `ci.yml` is not:
      message the lead with the exact change if CI needs one)
- [ ] Tests (offline, fake LLM + fake adapters): record then replay a two-specialist run with deliberately skewed
      completion order (one specialist's tools slower) and get identical evidence ids, LLM keys and graded result;
      replay with a changed prompt raises `StaleRecordingError`; baseline recordings still replay byte for byte
- [ ] `firebreak/activities/agents.py` changes only if the existing seams are insufficient (say why in the PR)
- [ ] PR description has a `## Progress entry`
