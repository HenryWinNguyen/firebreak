## Goal
The first live end-to-end run (2026-11-14, `inc_11276771…`, qwen3:8b on one Ollama) completed `REPORT_ONLY`, but
showed three problems. (1) The supervisor planned a task for `service_graph`, which is a tool, not a specialist; the
workflow ran it, it failed, and it showed up as a degraded source. (2) Ollama serves one request at a time, so three
parallel specialists at ~64–90 s per step need far more than the old 300 s, and so can triage/supervisor/synthesizer.
(3) With Ollama down, triage burned its 3 attempts in ~4 s and the incident escalated. Fix all three in the workflow.

## Definition of done
- [ ] Before fan-out, tasks whose `agent` is not in `SPECIALIST_AGENTS` are dropped: logged at WARNING with incident
      id and agent name, listed in `WorkflowOutcome.dropped_tasks` (as the agent names, plan order), and **not** added
      to `degraded_sources`. If no task is left, the outcome is `ESCALATED` with an `error` saying the plan named no
      known specialist. Tests for both, asserting `dropped_tasks`, `degraded_sources` and `final_state`
- [ ] Timeouts sized for a serial local model: triage 900 s, supervisor 1200 s, synthesizer 1800 s (module constants);
      specialists use `task.timeout_s` (v1.8 default 1800). DB activities unchanged
- [ ] Agent activities' retry policy backs off long enough to ride out an LLM server restart: initial interval ≥ 10 s,
      backoff 2, max 3 attempts total (so ≥ ~30 s between first and last attempt). Non-retryable errors stay
      non-retryable. A test asserts the policy values on the scheduled activity (history or a captured call), not just
      the constant
- [ ] `supervisor.md`: state that `service_graph` is a tool the supervisor may call, never an `agent` value; list the
      three names as the only valid values; drop the "300 s default" sentence (say: omit `timeout_s`)
- [ ] Existing workflow tests still pass (kill-the-worker test included); no test reaches a live Temporal
- [ ] PR description has a `## Progress entry`
